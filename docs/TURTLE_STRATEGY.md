# 海龜投資法（Turtle Trading）策略設計

## 背景與定位

舊「三盤口袋名單」自動模擬交易（`auto-pocket` 帳本）實跑約一個月後，2026-07-21 ~
09-18 期間總報酬 -5.83%（`data/auto_trade_log/` 逐日 log 實測），使用者要求以海龜
投資法為基礎設計第二套、完全獨立的模擬交易模型：`auto-turtle` 帳本。兩者**平行運
作、互不干擾**，方便用真金白銀等級的時間跨度直接比較績效，不做任何取代或下架舊
模型的動作。

海龜投資法是 1980 年代 Richard Dennis 教授一批交易新手（"Turtles"）的規則化趨勢
跟隨系統：用突破訊號進場、用波動度決定部位大小、用金字塔加碼放大贏家、用嚴格的
資金管理紀律避免任何一次錯誤把帳戶打殘。這套系統天生適合本專案的處境——零 LLM、
純門檻、每日跑一次、規則透明可重現。

## 為什麼選 System 2（55 日突破）而不是 System 1（20 日突破）

原始海龜法有兩套並行系統：
- System 1：20 日突破進場，但有「上一筆訊號若獲利就跳過」的過濾（避免連續假突破）。
- System 2：55 日突破進場，不做上一筆過濾。

本專案只實作 System 2，原因：
1. 55 日突破的訊號頻率較低、訊號品質較高（門檻更高），較適合本專案目前只有
   ~8 個月歷史資料、無法承受高頻交易噪音的處境。
2. System 1 的「上一筆是否獲利」過濾需要跨訊號的狀態追蹤，邏輯與測試複雜度顯著
   增加，換來的邊際效益（避免假突破連續發生）在 System 2 較長的窗口下本來就更少見。
3. 原始海龜法本身也建議「兩套系統擇一半數資金」或「只用 System 2」作為簡化版，
   單用 System 2 是被驗證過可行的簡化路徑。

## 核心指標

### N（波動單位，ATR 的另一種說法）

```
TR_t = max(high_t - low_t, |high_t - prev_close|, |low_t - prev_close|)
N_t  = mean(TR, 最近 20 日)
```

N 是海龜法的核心：所有部位大小、加碼間距、停損距離都用 N 的倍數表達，而不是用
固定百分比。理由是「同樣是 10% 的價格波動，對電力股和生技股的『正常噪音』意義完
全不同」——用 N 可以讓部位大小自動隨個股的實際波動度調整，波動大的股票天生分配
較少股數，波動小的股票分配較多股數，讓「一個 unit 的風險曝險」在不同股票間趨於
一致。

### Donchian 突破（55 日進場 / 20 日出場）

```
donchian_high(window) = 最近 window 日（不含當日）收盤價最高值
donchian_low(window)  = 最近 window 日（不含當日）收盤價最低值
```

- 進場：收盤 > 過去 55 日收盤最高值 → 觸發做多突破（只做多，不做空，現貨模擬帳戶
  無法放空）。
- 出場：收盤 < 過去 20 日收盤最低值 → 出場。

用「收盤」而非「日內高低」判斷突破，是因為系統是收盤後跑一次的日頻排程（GitHub
Actions），不是盤中即時監控，無法對盤中觸價做出反應。這是相對原始海龜法（盤中
觸價即成交）的簡化，詳見下方「已知限制」。

## 部位大小與金字塔加碼

### 為什麼是 1% risk per unit

```
unit_shares = floor(equity × UNIT_RISK_PCT / N)，再捨去到 100 股整數倍
```

1 個 unit 代表「N 的波動幅度 = 帳戶權益的 1%」。也就是說，若某檔股票從進場價位
往不利方向移動整整 1 個 N（原始海龜法用 N 當停損距離的基本單位），這個 unit 造成
的帳面損失大約是帳戶權益的 1%。這是海龜法刻意設計的保守值——用波動度而非固定金額
分配風險，讓帳戶不會因為單一部位波動過大而重傷。

`UNIT_RISK_PCT = 0.01`（1%）是原始海龜法的教學值，也是多數量化文獻引用的保守
基準；沒有選更高的值（如 2%），是因為本策略允許單一標的最多疊加到 4 個 unit，
若每個 unit 都取 2%，單一標的最大曝險會膨脹到 8% 权益的波動風險，對一個資料只有
8 個月、還沒被充分驗證的新模型而言過於激進。

### 金字塔加碼：為什麼 0.5N、最多 4 個 unit

```
價格從最近一次進場/加碼價再漲 0.5×N → 可以再加 1 個 unit（同一天最多加碼 1 次）
最多累積 4 個 unit（含首次進場）
```

金字塔加碼是趨勢跟隨策略的核心賺錢機制：讓部位隨著趨勢確立而放大，而不是一開始
就押滿。0.5N 的加碼間距（比原始海龜法常見的 0.5N~1N 區間取偏積極的一端）讓系統
在趨勢延續時能較快建立到滿倉位，但仍要求每次加碼都是「價格繼續往有利方向走」的
確認，不是無條件加碼。上限 4 個 unit 是原始海龜法的標準參數，超過這個數字邊際效
益遞減但集中度風險遞增。

### 停損只升不降：「整批停損線」設計

```
每次加碼（含首次進場）：整批停損線 = 這次加碼/進場價 − 2×N（用當次重新算的 N）
```

海龜法的停損不是盯著每個 unit 各自的停損，而是「這一整批倉位共用一條停損線」，
且這條線只會隨加碼往上收緊、不會下降。理由：
1. 一旦加碼，代表趨勢方向已被確認，此時把停損線收緊到接近最新進場價，是把已實現
   的浮盈保護起來，同時也是變相的「移動停損」。
2. 只升不降避免了「加碼後行情稍微拉回就整批砍在更差價位」的矛盾——如果每次加碼
   都重算一條更寬鬆的停損線，反而會讓總風險曝險隨加碼上升而不是下降。

`STOP_N_MULT = 2.0`（2 倍 N）是原始海龜法的標準停損距離，也是本專案在只有 8 個月
資料的回測中，維持能承受正常波動、又不至於讓單一部位虧損過大的折衷值。

## 出場優先序：停損 > Donchian 20 日突破

每日先檢查停損（收盤 < 停損線 → 全部出場），沒觸及才檢查 20 日 Donchian 出場。
停損優先的理由很直接：停損是「本來就該止血」的保護機制，Donchian 出場則是「順著
趨勢逆轉的訊號」離場，兩者同時觸發時代表虧損已經比預期更深，此時不該再等 Donchian
確認，應立刻用停損價出場止血。

## 資金管理紀律（風控上限）

### 為什麼要設總量上限與單日上限

`MAX_TOTAL_UNITS = 20`、`MAX_NEW_UNITS_PER_DAY = 4`：即使訊號本身完全合理，海龜
法也刻意限制「同時能承受多少個 1% 風險單位」與「一天最多能建立多少新曝險」。原因
是所有 unit 的風險雖然各自獨立設計為 1%，但同一天多檔股票同時觸發突破，往往代表
市場處於同一個總體因子（例如全市場情緒轉強）驅動之下，實際相關性遠高於「各自獨
立的 1%」這個假設所暗示的，若不設上限，一次系統性行情逆轉可能讓數十個 unit 同時
虧損，總曝險遠超帳戶能承受的範圍。

超過額度時，用「今日收盤相對 55 日高的超出幅度 / N」由大到小排序，優先給「突破
力道最強」的候選——這代表趨勢確立程度更高、訊號品質更好，比單純先到先得更合理。

### 回撤節流（drawdown throttle）：連續虧損後主動縮手

```
權益 ≤ 歷史高點 × (1 − 20%) → 新單位的 UNIT_RISK_PCT 減半（1% → 0.5%）
直到權益回升到 ≥ 歷史高點 × (1 − 10%) 才恢復正常
```

這是海龜法「連續虧損後縮手」的資金保護紀律，理由：任何規則化系統都會遇到連續
虧損的低潮期（尤其是趨勢跟隨策略，勝率天生偏低、靠少數大贏家撐報酬），若在低潮
期還維持全額風險曝險，帳戶會在系統本身尚未證明失效之前就先被侵蝕到無法恢復的
地步。縮手不是放棄策略，而是「用更小的賭注撐過噪音期，等訊號品質變好或帳戶回血
後再恢復正常曝險」。20%/10% 的雙門檻（觸發用 20%、恢復用更保守的 10%）避免了
「卡在門檻附近來回切換」的抖動。

### 再進場冷卻：避免假突破來回巴來巴去

```
某檔出場（不論停損或 Donchian）後，10 個日曆日內不可重新以「新倉」進場同一檔
```

突破策略最常見的失效模式是「假突破」：價格突破後立刻拉回觸發出場，然後很快又
重新突破，若沒有冷卻機制，系統會在同一檔股票上來回進出、每次都被小幅度巴一巴，
累積手續費與情緒成本（雖然本系統不計手續費，但頻繁進出本身就是策略品質變差的
訊號）。10 個日曆日的冷卻期讓系統有機會先觀察後續走勢，而不是立刻重新追價。

### 價格防呆

`MIN_PRICE_JPY = 50`（低於不交易）、`MAX_PRICE_AGE_DAYS = 5`（收盤價資料太舊不
進場）、`LOT_SIZE = 100`：延續舊三盤模型的防呆邏輯，避免雞蛋水餃股與錯價/分割
造成的異常訊號，以及用過期價格資料下單。

## 已知限制（誠實揭露，不誇大）

1. **收盤突破而非盤中觸價**：原始海龜法設計於盤中即時監控、觸價即成交的環境，
   本系統是收盤後跑一次的日頻排程，只能用收盤價判斷突破與出場，無法複製原始
   設計的即時反應速度。這會讓實際滑價與理論值有落差（通常對系統不利，因為錯過
   了最初的觸價點，等到收盤確認時價格可能已經走得更遠）。
2. **資料歷史極短**：目前 `data/cloud-cache` 只有約 8 個月的日 K，遠短於海龜法
   設計時假設的「跨多個景氣循環」樣本。回測結果（見
   `docs/TURTLE_BACKTEST_REPORT.md`）僅供起始基準參考，不能視為策略長期有效性
   的證明。
3. **存活偏誤**：候選池是「目前仍在快取中的股票」，缺少回測期間可能已下市/下櫃
   的股票，會讓歷史報酬率統計偏樂觀。
4. **不含手續費、滑價、稅負**：所有模擬都假設訊號能以當日收盤價足額成交。
5. **全市場掃描的資料新鮮度不一**：不同股票的 `data/cloud-cache` 同步時間點不同，
   `MAX_PRICE_AGE_DAYS` 會自然濾掉資料落後的股票，這代表候選池的「有效範圍」
   每天會因為資料同步進度而浮動，不是穩定的全市場覆蓋。

## 參數總表

所有數字定義在 `capystock/config.py` 的「海龜投資法模擬交易」區塊：

| 參數 | 值 | 意義 |
|---|---|---|
| `TURTLE_N_PERIOD` | 20 | N＝最近 20 日 TR 簡單平均 |
| `TURTLE_ENTRY_BREAKOUT_DAYS` | 55 | 進場：55 日收盤突破 |
| `TURTLE_EXIT_BREAKOUT_DAYS` | 20 | 出場：20 日收盤突破 |
| `TURTLE_UNIT_RISK_PCT` | 0.01 | 1 unit = 權益 1% 波動風險 |
| `TURTLE_STOP_N_MULT` | 2.0 | 停損 = 進場/加碼價 − 2×N |
| `TURTLE_PYRAMID_ADD_N_MULT` | 0.5 | 加碼間距 = 0.5×N |
| `TURTLE_MAX_UNITS_PER_MARKET` | 4 | 單一標的最多 4 個 unit |
| `TURTLE_MAX_TOTAL_UNITS` | 20 | 全帳本最多 20 unit |
| `TURTLE_MAX_NEW_UNITS_PER_DAY` | 4 | 單日最多新增 4 unit |
| `TURTLE_DRAWDOWN_THROTTLE_PCT` | 0.20 | 跌破高點 20% → 縮手 |
| `TURTLE_DRAWDOWN_RECOVER_PCT` | 0.10 | 回升到高點 -10% 內 → 恢復 |
| `TURTLE_REENTRY_COOLDOWN_DAYS` | 10 | 出場後 10 日曆日冷卻 |
| `TURTLE_MIN_PRICE_JPY` | 50 | 低價股防呆 |
| `TURTLE_MAX_PRICE_AGE_DAYS` | 5 | 過期價格防呆 |
| `TURTLE_LOT_SIZE` | 100 | 日股交易單位 |
| `TURTLE_INITIAL_CASH_JPY` | 3,000,000 | 起始資金（比照舊模型） |

## 實作對應

- 核心計算：`capystock/turtle.py`（純函式：`true_range` / `n_value` /
  `donchian_high` / `donchian_low` / `unit_size` / `pyramid_trigger` /
  `stop_line_for_unit` / `tighten_stop`），單測於 `tests/unit/test_turtle.py`。
- 全歷史回測：`scripts/backtest_turtle.py`，輸出
  `docs/EVIDENCES/turtle_backtest_2026-09-24.json` 與
  `docs/TURTLE_BACKTEST_REPORT.md`。
- 每日模擬交易：`api/services/turtle_trade_service.py`（`TurtleConfig` /
  `select_new_entries` / `select_pyramid_adds` / `evaluate_exit` /
  `next_risk_pct` / `run_daily`），單測於 `tests/unit/test_turtle_trade_service.py`。
- 排程入口：`scripts/run_turtle_trade.py`，由
  `.github/workflows/paper-trade-turtle.yml` 每個交易日呼叫，完全平行於舊模型的
  `paper-trade.yml`，不共用任何檔案。
