## 股價 + 成交量（自動）

### 怎麼取得

**CapyStock 已自動化 ✅**  
系統每天下午 3:30（日本收盤時間）自動從 **kabutan.jp** 爬取。

### 數據源

| 來源 | 特點 | 限制 |
|------|------|------|
| **kabutan.jp** | 免費、即時、日本股民最多用 | 需爬蟲；快速更新需等 5–10 分鐘 |
| **yfinance** | 免費備援、國際通用 | 延遲 ~20 分鐘；日本股票支援不完整 |

但若想**手動更新**：
1. 進入 http://localhost:8000 → 左邊欄「資料管理」
2. 看到表格，按「批量更新」
3. 全選（預設）→ 點「執行」
4. 等待 30 秒 → 所有股票行情更新完畢

### 若更新失敗怎麼辦

**自動 fallback**：
- Kabutan 爬蟲失敗 → 自動改用 yfinance
- yfinance 也失敗 → 系統記錄在 log，並發 email 通知你

若兩個都失敗（罕見），你可以**手動上傳 CSV**：
1. 從 Yahoo Finance 下載股價 CSV
2. 進入「資料管理」→「上傳」
3. 拖拉 CSV 檔案進去
4. 系統自動識別並導入

## 信用残週報（手動或自動）

### 什麼是信用残

**信用残** = 信用交易未平倉部位
- **融資（margin long）** — 散戶借錢買股的部位
- **融券（margin short）** — 散戶借股放空的部位

**判讀**：
- 融資↓ 散戶認賠出場
- 融資↓ + 外資在買 = 主力在吃貨（散戶被洗出來）✅ **吃貨訊號**

### 數據源及取法

#### 方法 1：Yahoo Finance Japan（推薦，免費 + 自動）

**來源**：https://info.finance.yahoo.co.jp/

**操作**：
1. 打開上述網址
2. 搜尋股票代號（e.g. `7203`）
3. 在「信用残高」分頁看週度數據（每週四公布上週五資料）
4. 往下滾找到表格：
   ```
   信用買取残 (千株) | 信用売却残 (千株)
   18,200            | 4,100
   ```

**複製格式**：
```csv
week,margin_long,margin_short
2026-05-10,18200,4100
2026-05-17,19100,3900
2026-05-24,22500,3500
```

#### 方法 2：Minkabu（備援，免費但手動）

**來源**：https://minkabu.jp/

1. 搜尋股票 → 「チャート」分頁
2. 左邊「信用買残」選項
3. 往下看週度折線圖
4. 右邊資料表往下滾，找到詳細數據

**優點**：視覺化更清楚  
**缺點**：需手動複製，無 API

#### 方法 3：日本興業銀行（IBJ）信用残報告（官方，但須付費）

**來源**：日本交易所集團（JPX）官方報告  
**取得**：需購買訂閱（￥ ~5,000/月）  
**適合**：機構投資人

### 導入系統

#### 自動導入（推薦）

若你有 Python 環境，可用 CapyStock 內建的 ingest 工具：

```bash
# 從 Yahoo Finance 爬信用残（7203 裕日汽）
python -m capystock.main ingest margin 7203

# 結果會存到：data/cache/7203_margin.csv
```

#### 手動上傳（簡單，無須 CLI）

1. 在 Yahoo Finance JP 複製信用残數據到 CSV：
   ```csv
   week,margin_long,margin_short
   2026-05-10,18200,4100
   2026-05-17,19100,3900
   ```

2. 進入 http://localhost:8000 → 「資料管理」→「上傳」
3. 拖拉 CSV 或點選檔案
4. 系統預覽 → 確認欄位名稱識別（綠色 ✅）
5. 點「導入」

**系統會自動**：
- 轉換單位（若你填的是「股」而非「千株」）
- 檢查時間序列有無重複
- 存到 `data/cache/{CODE}_margin.csv`

### 使用頻率

- **推薦**：每週一次（週四公布新一週數據）
- **最少**：月一次（關鍵的「籌碼集中」判斷）
- **若要追求即時**：日一次（但數據會有 1–4 天延遲）

## 投資部門別買賣超（手動或自動）

### 什麼是投資部門別

**投資部門別** = 按買家身份分類的每日買賣超
```
日期        外資買賣超    法人買賣超    個人買賣超
2026-05-10  +3,200       +1,500       -4,800
2026-05-11  -1,200       -800         +2,100
```

**判讀**：
- 外資連 5 日買超 + 個人連日賣超 = 主力在吃貨（散戶被倒出場）✅ **吃貨訊號**
- 外資連 3 日賣超（≥10 日買超 20%）= 主力在倒貨 🔴 **出場警告**

### 數據源及取法

#### 方法 1：JPX 每週報告（官方，免費）

**來源**：https://www.jpx.co.jp/markets/statistics-equities/

**操作**：
1. 打開上述連結
2. 找「投資家別売買動向」（投資部門別買賣動向）
3. 下載 Excel：「日経平均採用銘柄」或「全上場銘柄」
4. 開啟 Excel → 篩選你追蹤的股票代號
5. 複製過去 10 日的 3 欄數據（外資、法人、個人）

**複製格式**：
```csv
date,foreign_net,institution_net,individual_net
2026-05-06,+3200,+1500,-4800
2026-05-07,-1200,-800,+2100
2026-05-08,+2800,+600,-3400
```

**單位**：千株（＝kabutan 一樣）

#### 方法 2：Yahoo Finance JP（簡單，但需手動逐日查）

**來源**：https://stocks.finance.yahoo.co.jp/

1. 搜尋股票 → 「投資家別売買」分頁
2. 每行是一天
3. 複製「外資」「法人」「個人」三欄

**缺點**：需逐日點擊，量大時很煩

#### 方法 3：Kabutan（部分股票有）

**來源**：https://kabutan.jp/

1. 搜尋股票 → 「売買代金」分頁
2. 下方有「投資家別」圖表
3. 點「テーブル表示」看表格
4. 複製最近 5–10 日

**限制**：非所有股票都有完整歷史數據

### 導入系統

#### 手動上傳（推薦新手）

1. 從上述任一來源複製 CSV：
   ```csv
   date,foreign_net,institution_net,individual_net
   2026-05-06,+3200,+1500,-4800
   2026-05-07,-1200,-800,+2100
   ```
   
   或用日文欄位名（系統自動識別）：
   ```csv
   日付,外資,法人,個人
   2026-05-06,+3200,+1500,-4800
   ```

2. 進入「資料管理」→「上傳」
3. 拖拉 CSV
4. 系統預覽 → 確認（綠色 ✅）→ 點「導入」

#### 自動下載（進階，需手動設定）

若你有 JPX Excel 報告的本地副本，可用 CLI：

```bash
python -m capystock.main ingest jpx-weekly /path/to/JPX_投資家別_2026-05.xlsx
```

系統會自動：
- 解析 Excel（支援 CP932 日文編碼）
- 逐檔股票估算投資部門別
- 存到 `data/cache/{CODE}_flow.csv`

### 使用頻率

- **推薦**：每週一次（每週五公布上一週數據）
- **最少**：月一次
- **若要吃貨訊號即時性**：日一次（但準確性↓，因延遲 1 天）

## EDINET 大量保有申報（自動）

### 什麼是 EDINET 申報

**EDINET** = 日本金融廳的上市公司公開資訊系統

主要看：
- **5% rule（大量保有報告）** — 持股 >5% 的外資/機構申報
- 持股變化 → 判斷外資是建倉還是減倉

**例**：
```
2026-05-08：投資銀行 A（外資）申報持股 5.1%（新進場）
2026-05-09：技術基金 B 申報持股 8.3%（增持）
```

### 數據源

**金融廳 EDINET API**：https://disclosure2.edinet-fsa.go.jp/

免費 API，需申請 key。

### 設定（一次性）

1. **申請 API key**（5 分鐘）
   - 打開 https://disclosure2.edinet-fsa.go.jp/weee0020.aspx
   - 填入你的 email、企業/個人名稱
   - 立刻收到 key（可立刻用，無審核期）

2. **保存到系統**
   - 編輯 `data/.env`，加一行：
     ```
     EDINET_API_KEY=<你收到的 key>
     ```

3. **驗證設定**
   ```bash
   python -m capystock.main edinet --days 3
   ```
   
   若看到股票列表 + 5% rule 申報 → 設定成功 ✅

### 使用方式

CapyStock 已**全自動化** ✅

每次執行 `check` 時，系統自動：
1. 回掃最近 3 日的 EDINET 申報
2. 篩選你的追蹤清單中的股票
3. 顯示「大量保有申報」卡片

**手動查詢**（可選）：
```bash
# 查最近 7 日申報
python -m capystock.main edinet --days 7

# 掃全市場（不限追蹤清單）
python -m capystock.main edinet --days 3 --all

# 執行 check 時排除 EDINET
python -m capystock.main check --no-edinet
```

## 常見問題

### Q1：我是非技術人員，不想用 CLI，行嗎？

**可以！** CapyStock 網頁界面已支援所有手動上傳。

完全無須 CLI，只需：
1. 從網站複製 CSV
2. 進入「資料管理」→「上傳」
3. 拖拉檔案 → 完成

### Q2：信用残和法人買賣，到底要不要都上傳？

**推薦都上傳**，但優先級：
1. **信用残** — 判斷「籌碼集中」訊號（必須）
2. **法人買賣** — 判斷「主力吃貨」訊號（強烈建議）

若只有一個，選「信用残」。

### Q3：數據有延遲（JPX 慢 1–3 天），會不會錯過信號？

**會有延遲，但系統有設計補償**：
- 信用残延遲 4–5 天 → 系統只用它做「事後確認」，不做進場決策
- 法人買賣延遲 1 天 → 系統做「進場輔助判斷」，不單獨決策
- **股價實時** → 是進場/停損的主要判斷

結論：數據延遲無法避免，但不會影響停損執行（股價實時）。

### Q4：EDINET API 需要付費嗎？

**完全免費**。日本金融廳提供免費 API，只需申請 key（無審核、無費用）。

### Q5：我下載的 CSV 格式和範例不一樣，系統認得嗎？

**系統很聰明**，自動識別常見的欄位名：
- 「margin_long」「融資」「信用買残」都認得
- 「2026-05-10」「2026/05/10」都認得
- 「千株」和「株」單位會自動轉換

若不確定，上傳後看預覽 → 欄位名會標示（綠✅ 或 紅❌）→ 再決定是否導入。

### Q6：月底/年底有沒有推薦的數據「大清理」流程？

**推薦月一次（月底）**：
1. 檢查所有股票的「年齡標籤」
2. 若有超過 1 週的紅色 → 補回最新數據
3. 檢查是否有重複週期的信用残（系統會警告）
4. 清理已下市的股票（移除 watchlist）

**年度（12 月）**：
1. 導出 1 整年的警告 log → 存檔（作為復盤參考）
2. 評估「每檔股票」的真實收益率 vs 系統預測 → 調整參數
