## 模擬交易大改（IMP-002）

來源：使用者 2026-06-07 口述需求。狀態：⬜ 待實裝。

### 需求（使用者 2026-06-07 二次澄清後定版）

#### A. 資料模型：帳本（資料夾）＋ 交易（主體）
- **帳本（ledger）**：可**新增／刪除**。目前**無特殊功能**，純粹當資料夾用，把多筆交易分組。
- **交易（trade）＝主體單位**（不是以股票為主體）：
  - 一個帳本可放**複數筆**交易；**同一股票可在同一帳本重複出現**，各筆**獨立存在**。
  - 例：同一帳本內 `5/30 買 Toyota 400 元 200 股` 與 `6/2 買 Toyota 410 元 100 股` 是兩筆獨立交易，**不合併、不算平均成本**。
  - 每筆交易欄位：股票代碼、購入時價、購入股數、購入日、停損% `N`、停利% `M`、狀態（持有/已出場）、出場價、出場日、出場原因、損益。

#### B. 加入流程（從 /pocket 用 popup）
- 點某檔「模擬交易」按鈕 → 跳 **popup**，使用者填：
  1. **購入時價**（預設帶入該檔現價，**可改**）
  2. **購入股數**
  3. **移動停損 `N`%**、**移動停利 `M`%**（使用者自訂）
  4. 選擇要加入哪個帳本（或新建帳本）
- 確認 → 在該帳本**新增一筆交易**，**不跳轉頁面**。

#### C. 出場邏輯：棘輪式移動停損（只升不降，以最高收盤為錨）
- 一筆交易**只有一條線**（停損線）；當它升到進場價之上，概念上叫「停利線」，但**系統內是同一條線**。
- 規則：
  - 進場時：`high_water = 購入時價`，`停損線 = 購入時價 × (1 − N%)`。
  - 每日**收盤後**：若**當日收盤 > high_water** → 更新 `high_water = 當日收盤`、`停損線 = high_water × (1 − N%)`（**只會往上，永不下降**）。
  - 若當日收盤未創新高 → high_water 與停損線**維持不動**。
  - 出場：當某日**收盤價 < 停損線** → 以**該日收盤價**出場。
- 判定基準＝**當日收盤價**（不看盤中高低）。
- 驗算（進場 100、N=10%）：
  | 事件 | high_water | 停損線 | 動作 |
  |---|---|---|---|
  | 進場 100 | 100 | 90 | 持有 |
  | 收 105 | 105 | 94.5 | 持有（停損上移到 94.5） |
  | 收 95（另一情境，先前未破 100） | 100 | 90 | 持有（停損不動，95>90） |
  | 收 91 | 100 | 90 | 持有 |
  | 收 89 | 100 | 90 | **出場**（收盤 < 90） |
- 註：N 為單一移動停損%。原先的「固定停利 M%」依此定義已併入同一條線（停損升過進場價即為鎖利）。〔待確認：M 是否還要保留為「另一個硬停利上限」，或完全取消只留 N。〕

#### D. 完全移除回測
- 使用者**不需要回測機能**，**完全拔掉**（不是隱藏）：
  - `/simulation/new` 的「回測 vs 模擬交易」類型選擇、技術指標條件 UI、Sweep（策略參數網格回測）整頁與入口、`backtest_engine`、相關 schema/router/前端路由。
  - 依絕對規則，移除檔案一律改名加 `DELETE_` prefix，不真 `rm`。
  - 模擬交易頁最終只剩「跟單帳本」。

### 已確認（2026-06-07）
- 觸發判定基準：**當日收盤價**。
- 移動停損：**只升不降（棘輪式）**，以最高收盤為錨。
- 購入股數：**必填**，無預設值。

### 已確認（補）
- **取消固定停利 M**：popup 只填單一「移動停損 N%」，停利由同一條棘輪線升過進場價後自然形成。（使用者選 a，2026-06-07）
