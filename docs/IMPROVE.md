## 模擬交易大改（IMP-002）

來源：使用者 2026-06-07 口述需求。狀態：⬜ 待實裝。

### 需求（使用者原話整理）
1. **進場價＝使用者可設定，但要有預設值**：
   - 從 `/pocket` 三盤口袋名單點某檔的「模擬交易」按鈕 → **跳出 popup** 讓使用者**確認購入成本**（預設帶入該檔現價，可改）。
   - 確認後直接把該檔加入模擬交易帳本，**不跳轉頁面**（見第 4 點）。
2. **停損停利＝沿用「跟單帳本」的移動式停利法**（trailing take-profit / 移動停利）：
   - 即現有 `docs/PAPER_TRADING.md` 的帳本模型，但出場改採移動式停利（隨價格新高上移停利線，回落觸發出場），取代固定停利%。
   - 停損停利的具體 trailing 參數待設計（可參考 analyzer 既有三階段移動停損 `TRAILING_STAGE*` / Chandelier 概念）。
3. **移除回測（backtest）**：
   - 使用者不做技術線型模型，回測相關功能/UI/規則「全部拿掉」。
   - 影響面：`/simulation/new` 的「回測 vs 模擬交易」類型選擇、技術指標條件 UI、`backtest_engine` 入口、Sweep（策略參數網格回測）入口等，需逐一確認是移除或隱藏。
4. **加入方式＝只從口袋名單新增，不靠頁面轉移**：
   - `/pocket` 每檔只做兩件事：**加入模擬交易**（popup 確認成本）或**加入追蹤清單**。
   - 因此目前 /pocket「模擬交易」按鈕導向 `/simulation/new?code=` 的行為要**改成 popup 直接加入帳本**，不再跳轉。

### 待釐清（實裝前需使用者確認）
- 移動停利的觸發規則與參數（回落幾 % 出場？是否設保本階段？是否要硬停損下限？）。
- 加入帳本時，除了購入成本，是否要同時輸入股數／使用預設股數？
- 一個股票可否加入多個帳本，或固定單一帳本？popup 是否要選帳本？
- 「移除回測」是整段刪除（依絕對規則改 `DELETE_` 而非真刪）還是僅前端隱藏入口、後端保留？

### 實裝註記
- 目前 /pocket 的「模擬交易」按鈕（`toSimulation`，導向 `/simulation/new`）為過渡實作，本案落地時改為 popup。
- 後端帳本（ledger）模型見 `api/services/simulation_service.py` 與 `docs/PAPER_TRADING.md`。
